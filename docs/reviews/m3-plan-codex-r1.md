1. **vtt-5su.2 — blocker — The documentation bead is not self-contained.** It must copy exact tables from `.3`, but its agent receives only its own text and named documentation; `PROTOCOL.md` does not yet exist. Several decisions also leave implementation details to later beads. **Change:** put the complete protocol contract in `.2` or an existing document it cites, and make `.3` implement that single authoritative contract. The local bead export has complete tables; the pasted tables’ ellipses are display truncation.

2. **vtt-5su.3, .6 — blocker — The prescribed wire types cannot represent the required redaction.** `Value | ErrorValue | RedactedValue` does not allow redacted entries inside `Value`’s lists or viewers sets. Likewise, `GroupView.effects: Effect[]` cannot contain redacted stored values. **Change:** define recursive wire-value types and separate presentation-effect types, while retaining canonical schemas for unfiltered document data. Require nested-redaction round trips through the actual message parsers.

3. **vtt-5su.3, .11 — blocker — Reusing the existing schemas unchanged prevents the promised JSON Schema generation.** The repository’s `ValueSchema` and `CellContentSchema` use `z.custom`; the installed Zod rejects conversion with “Custom types cannot be represented in JSON Schema.” These occur inside transaction inputs. **Change:** assign JSON-Schema-compatible wire schemas or explicit conversion metadata to `.3`; its Done-when must successfully export the complete transaction input schema and `WireOp` schema. Do not leave discovery of this incompatibility to `.11`.

4. **vtt-5su.6, .8 — blocker — Character-view filtering is incomplete for logs and explain.** A creation effect can expose every stored cell, formula and action of an otherwise visible object. Formula cell effects and action-field effects likewise expose source despite D11. `explainCell` specifies filtering dependencies but does not explicitly reject an invisible root object or unreadable root cell; `explainAction` has the same missing object check. **Change:** specify filtering for every effect variant, omit character-inaccessible source and metadata, and require indistinguishable `not_found` responses for inaccessible explain targets. Test public objects with private cells, creation snapshots, formula overrides and action edits.

5. **vtt-5su.6 — should-fix — Reference redaction treats board references as invisible-object references.** The structural `board` cell contains a reference to a board, while `canSeeObject` concerns objects. Applying the stated rule indiscriminately can redact placement information every character client needs. **Change:** distinguish board references from object references explicitly; boards are not a security boundary under DESIGN §4.3. Add a character-view test preserving a visible token’s board reference.

6. **vtt-5su.9 — blocker — The candidate algorithm misses committed changes.** It omits `summary.changedCells` and general field effects. Consequently, a literal tag/shape edit, reorder, flag change, or create/remove inside a container can leave the object or its parent’s `contents` stale when no formula dependency makes it dirty. Changing the viewer’s `is_character` flag can invalidate an entire character view without triggering the visibility branch. **Change:** derive candidates from all changed cells and affected fields/containers, and define visibility invalidation for character-flag changes. Add deterministic tests for every omitted operation; the random test currently does not cover them all.

7. **vtt-5su.9, vtt-75c.18 — blocker — A required upstream output has no dependency.** `.9` consumes `ChangeSummary.actionsChanged`, which `vtt-75c.18` introduces, but `.9` can run without it. Board-rename detection is also required without a specified summary field or effect-inspection rule. **Change:** record `.9 → vtt-75c.18` and explicitly assign board-change detection to either the summary producer or inspection of committed board effects.

8. **vtt-5su.2, .9 — should-fix — The lazy-evaluation requirement is impossible as stated.** “Other dirty cells stay dirty” conflicts with evaluating a subscribed formula whose dependency is outside the subscription. Visibility and cover computation can also require out-of-scope reads. **Change:** permit transitive dependency and visibility/geometry reads needed to construct subscribed views; require only unrelated dirty cells to remain unevaluated. Test both cases.

9. **vtt-5su.3, .7, .9 — blocker — Log subscriptions cannot maintain current-visibility filtering.** They send only the new group and an undone target. Hiding or removing an object changes older group views, but the protocol has no group-removal mechanism. Previously sent private information therefore remains in the mirror, and newly visible history never appears. **Change:** define a bounded log window with replacement/reset or group upsert/removal deltas. Extend mirror equivalence tests to log scopes across reveal, hide, remove and undo.

10. **vtt-5su.5 — blocker — Post-execution stale checking cannot deliver its deleted-object acceptance case.** A write to an object removed since `base_revision` fails in the primitive before producing effects, so execution never reaches the promised `obj:` conflict check. **Change:** define conflict detection and rejection precedence for operations whose targets or destinations disappeared. Use a conservative intended-write set or a specified failure-path conflict check, while retaining effects-based checking for successful speculative execution. Also define the retained-history floor when compaction leaves zero groups.

11. **vtt-5su.5 — should-fix — The permitted conflict-helper edit disagrees with the existing implementation.** `keysIntersect` already exists in `store/effects.ts` and returns a boolean; `.5` proposes exporting a same-named helper from `store/undo.ts` returning keys. Both would reach the package exports. **Change:** consume the existing `keysConflict`/`keysIntersect` API and add a distinctly named helper for reporting intersecting keys, with an explicitly owned file.

12. **vtt-5su.2, .5, .7, .11 — blocker — Automatic retries cross the boundary of the deduplication guarantee.** `.11` retries after reconnection, but the cache disappears on authority restart. A committed command whose response was lost can then execute again. A server-wide cache keyed only by `txn_id` also silently conflates different actors or payloads. **Change:** scope deduplication to a stable client/actor identity and request fingerprint; reject mismatched reuse. Expose the authority session identity and retry only within the same session and stated retention guarantee. Across restarts, report an uncertain outcome unless persistent deduplication moves into M3.

13. **vtt-5su.3, .8 — should-fix — `changes_since` lacks a reliable pagination cursor.** It limits retained groups before dropping invisible ones, but returns the table’s current revision rather than the last scanned revision. A page can contain no visible groups and still have `more: true`, leaving the caller unable to advance safely. **Change:** return an explicit next/scanned revision cursor and define truncation for empty retained history. Test multiple invisible pages followed by a visible group.

14. **vtt-5su.4, .10 — blocker — Save ordering and revision ownership are unspecified.** Atomic replacement does not prevent overlapping saves from replacing a newer snapshot with an older one. Commits can also occur during asynchronous I/O; marking the current revision saved would then lose unsaved-state tracking. `.10` calls handlers synchronous even though `save()` is asynchronous. **Change:** serialize saves, capture the saved revision with the serialized snapshot, preserve later dirty revisions, and make shutdown await outstanding I/O before releasing the lock. Define router ordering around asynchronous handlers and test a commit during a delayed save.

15. **vtt-5su.4 — should-fix — Persistence omits asset retention and autonomous failure retry.** M2’s `saveTable` requires the asset list, but `TableHost` does not own or preserve it. Also, cancelling the schedule when saving leaves “retry at the next schedule” undefined if the save fails and no further commits occur. **Change:** retain loaded assets through every save and explicitly schedule bounded retries for unsaved revisions. Test an asset-bearing file and a failed autosave followed by no additional edits.

16. **vtt-5su.6 — should-fix — Board-cover enumeration assumes an upstream API that does not exist.** M2 provides `opaqueZonesCovering(object)`, not an enumeration of all covers on a board. That cannot supply a hidden room cover on an otherwise empty board without additional logic. **Change:** explicitly assign board-wide zone enumeration and geometry classification to `.6`, or add a prerequisite API bead. Specify which board covers an objects-scope subscription receives, including contained objects, and test empty boards and undetermined geometry.

17. **vtt-5su.7, .11 — should-fix — The client/MCP subscription interface is incomplete.** MCP needs table metadata and before/after mirror state associated with a group header, but `.7` does not expose `table` or specify delta-event payloads and callback timing. Reconnection can change the wire subscription ID, while MCP callers retain the old ID for polling and resource reads. **Change:** freeze the event contract, expose welcome metadata, and keep a stable MCP subscription handle mapped to changing wire IDs. Test polling, resource reads and unsubscribe after resync.

18. **vtt-5su.11 — should-fix — MCP change buffers omit observable changes.** Their records carry cell changes and object IDs but omit action definitions and object flags. `set_actions` or `set_character_flag` can therefore yield a notification with no usable description of what changed. **Change:** include object-view changes or explicit action/flag changes, and define how clients recover current state after overflow. Add tests beyond cell writes.

19. **vtt-5su.13 — blocker — The specified undo assertion is impossible after the preceding successful agent write.** Once the agent commits the disjoint `damage_dice` edit, `undo {type:"mine"}` selects that newer group. Pinning the earlier card-creation index must produce `undo_target_changed`, not `undo_conflict`. **Change:** target the card group explicitly, or perform the conflict assertion before the later agent commit. Test target mismatch separately.

20. **vtt-5su.12 — should-fix — The fixture adapter confuses visibility with redaction and lacks its comparison hook.** A readable cell containing a redacted reference is still a visible cell under FIXTURES §7. Also, comparing snapshots after every direct-runner step requires an observation API not promised by M2’s `RunReport`; exporting an existing helper may not suffice. **Change:** define `cell_visible` by cell presence, and authorize a narrowly scoped per-step observation hook in the direct runner or add it upstream.

21. **vtt-5su.2, .3, .9, .10 — should-fix — Size limits do not define how large initial views are delivered.** Full `all`/board subscriptions can exceed the message or buffered-byte limits on the few-thousand-object tables DESIGN §7 explicitly targets. Reconnecting and resubscribing can reproduce the same failure indefinitely. **Change:** define bounded snapshot delivery—pagination or chunking with a revision-consistent completion boundary—and test a large initial subscription over the real transport.

22. **vtt-5su.8, .10, .11 — should-fix — Several beads bundle independently reviewable subsystems.** `.8` combines query pagination/geometry with dependency and error tracing; `.10` combines routing/authentication with process and discovery lifecycle; `.11` combines tool adaptation with buffering, retry and stdio lifecycle. **Change:** split those responsibilities into separate beads with explicit contracts and file ownership. Preserve CLAUDE.md’s existing shared-index export convention; those additive export lines alone do not warrant serializing every bead.

**Overall verdict: not ready to implement.** First resolve the wire-schema/redaction contracts, subscription completeness, stale-write and retry semantics, persistence ordering, missing upstream dependency, and contradictory acceptance assertion. Then split the broad beads and make their cross-agent interfaces explicit.
