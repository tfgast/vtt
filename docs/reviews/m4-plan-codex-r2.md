1. **vtt-3l6.14, .15, .16, .17 — blocker: UI bundles collide with table-image routes.** Vite’s current default emits JavaScript/CSS under `/assets/`. The asset handler runs before the UI handler and returns 404 for paths absent from `host.assets`, so a successfully built UI can fail to load. **Change:** give built UI resources a separate namespace, such as `/ui-static/`, owned by .15. Add an acceptance check that builds the actual UI, serves it through both handlers, and successfully fetches its referenced bundles.

2. **vtt-3l6.15 — blocker: session injection is not restricted to development.** `transformIndexHtml` also runs during builds. As specified, building with credentials available embeds a session token in `dist/index.html`; production serving then injects another session element. `readBootstrap()` can read the stale build-time token. **Change:** make `vttSession()` serve-only, ensure production output contains no credentials or session element, and test that production serving injects exactly one element containing the current credentials.

3. **vtt-3l6.4, .5, .21, .22 — blocker: the shared runtime interfaces do not agree.** .21 supplies `write(session, …)`, but .22 calls `session.write(…)`. Tool context lacks `activeBoard`, although creation and movement require it; `Scene` does not expose it either. The hook returns overlays and callbacks, but no specified path exposes preview geometry to .17’s `buildScene`, and camera effects have no declared state owner. **Change:** publish one consistent contract specifying the write port, active board, camera ownership/update port, preview snapshot, and hook outputs. Require a contract test that connects these interfaces without casts or invented adapters.

4. **vtt-3l6.8, .22 — blocker: creation continuations are not representable correctly.** .8 requires selecting the created object *and then* switching to select unless Shift is held. .22 permits only one continuation. It also interprets `opIndex` as an array index in `created`, whereas PROTOCOL §4 returns records carrying `op_index`; these differ for mixed transactions. **Change:** support ordered continuations, or explicitly assign tool switching to the settled-event reducer. Resolve created/spawned objects by matching `op_index`. Test mixed transactions and both Shift paths.

5. **vtt-3l6.3, .11, .13 — blocker: the promised broken-reference repair cannot be performed.** .3 makes an error, including a dangling-reference `#REF`, unsupported; .11 and .13 consequently open it read-only. Yet .11 must repair that same dangling reference by typing `@goblin2`, and DESIGN §4.6 requires repair. **Change:** distinguish “cannot reconstruct an editable literal” from “cannot replace this value.” Provide an explicit replacement editor for writable cells with unsupported results, while preserving formula-source editing. Test repairing a dangling literal reference through the actual UI.

6. **vtt-3l6.3, .11, .13 — should-fix: input serialization does not satisfy its round-trip contract.** `valueToInputText` lacks cell context even though `name` and `visible_to` have special parsing. A name containing `12` or `=x` would receive generic quoting, which the name parser preserves verbatim. Lists of references also cannot round-trip through the prescribed formula parser because `@id` is only handled at the top level. Trimming unchanged input additionally suppresses intentional whitespace changes to names. **Change:** make serialization cell-aware, define recursive list input syntax including references and quoted text, and compare text edits without discarding significant whitespace. Add these cases to the round-trip tests.

7. **vtt-3l6.16 — blocker: asset persistence requires more than `addAsset()`.** The existing `TableHost` coalesces saves and decides whether shutdown needs a save using document revision alone. An import deliberately changes no revision, so importing into an already-saved table and calling `save()` can leave the new asset absent from the file. An import during an in-flight save creates another same-revision race. **Change:** explicitly extend this bead’s ownership to save bookkeeping, using an asset generation or equivalent dirty state alongside revision. Test import-without-commit followed by save, import during a save, and shutdown after import.

8. **vtt-3l6.4, .22, .8, .17 — should-fix: asynchronous interactions lack board/tool-switch lifecycle rules.** The plan captures revisions but does not define what happens when the user switches boards or tools while dragging, choosing a file, uploading, or awaiting a write. A late upload can reach the wrong active tool; a held preview or continuation can affect a different board. **Change:** capture the destination board and interaction identity at interaction start, define cancellation and late-result handling, and specify when committed continuations may change current selection/tool state. Test board and tool changes during both upload and pending writes.

9. **vtt-3l6.12 — should-fix: contents reordering captures the wrong revision.** “Every write captures `baseRevision` at the click” does not define drag-to-reorder correctly. The permutation is based on the order at drag start; capturing a later revision can apply it to a concurrently changed list without a stale-write rejection. **Change:** capture the revision and ordered ids at drag start, submit against that revision, and test another client reordering or changing membership before release.

10. **vtt-3l6.7, .12 — should-fix: zone-hover tracing is inaccessible over a map image.** `hitsAt` prioritizes every non-zone over zones, and hover always uses its first result. A room zone over the dungeon map therefore reports the image as hovered. Alt-click changes selection, but no rule makes the selected zone the hover target; the object list only specifies clicking. **Change:** define an explicit way to hover such zones—for example, object-list hover driving `hoveredZone`, plus a rule for the cycled canvas target—and test tracing a room lying over an imported map.

11. **vtt-3l6.8, .9 — should-fix: polygon validation has an unresolved ownership/dependency boundary.** .8 owns the exported `isSimplePolygon` helper; .9 must reject the same invalid polygons but neither depends on .8 nor names another shared validator. Independent agents can duplicate the predicate and disagree on edge cases. **Change:** move validation into an earlier shared geometry bead and make both consumers depend on it, or add `.9 → .8` and explicitly require reuse. Give the shared validator the degenerate and boundary cases both tools must obey.

12. **vtt-3l6.22 — should-fix: this is larger than a contract/framework bead.** It combines public types, generic tool state, registry, navigation reducer, asynchronous effect execution, preview lifetime, upload orchestration, and React integration. Its completion blocks nearly every interactive feature, and fake-port tests alone do not establish the composition contract. **Change:** split public contracts and pure navigation from the asynchronous runner/React binding. Make the runtime bead depend on the contracts and .21; have concrete tools and canvas depend on the smaller contract bead, with integration tests depending on the runtime.

13. **vtt-3l6.12 — should-fix: inspector composition and tracing are independently reviewable work.** The bead owns five components, containment navigation/reordering, object commands, action presentation, and a viewer-sensitive asynchronous query/cache controller. The tracing controller has its own lifecycle and race-test matrix. **Change:** split tracing into its own bead with exclusive ownership of `tracing.ts`, its tests, and highlight updates. Keep inspector components together; make .17 depend on both.

14. **vtt-3l6.18 — should-fix: the final six-cover assertion lacks a required UI transition.** Step 5 moves the PC out of room 2 and puts a die on that PC, but does not require leaving view-as or moving both objects outside all covered rooms before editing. The inspector is read-only in view-as, and a covered die cannot be selected there. **Change:** explicitly return to GM before the die edits, place the PC and die in an uncovered area outside all six zones, then switch back to the PC for the final six-cover assertion. Specify numeric AC/bonus values that make the asserted HIT true/false outcomes deterministic.

**Overall verdict: not ready to implement.** Resolve the serving/bootstrap failures, shared runtime contracts, broken-reference editing, and asset-save bookkeeping first. Then tighten interaction lifecycle rules and split the two broad beads before dispatching independent agents.
