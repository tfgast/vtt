1. **vtt-1xv.5 — blocker — The documentation bead lacks its decision inputs.** It requires the “Q4 table,” Q8 encoding, Q18 examples, and decision-log rows “as written in section 4,” but neither its text nor the supplied planning bead contains those materials. An isolated agent must invent accepted decisions. **Change:** include the complete decision payload or cite a checked-in document containing it. Resolve vtt-1xv.2–.4 during planning and make .5 the sole owner of recording their outcomes.

2. **vtt-1xv.8, vtt-1xv.11 — blocker — Transaction ownership prevents the required stale-write check.** `.8` calls `transactWithDice` and returns a committed group. `.11` then needs to inspect the effects and abort before commit. The existing helper commits before returning; resetting dice afterward cannot retract notifications or the committed document. **Change:** define an execution-within-transaction API, or a pre-commit validation callback, in .8. Require .11 to check touched keys inside that transaction. Test that rejection changes neither document, revision, log, notifications, nor dice position.

3. **vtt-1xv.5, vtt-1xv.6 — should-fix — The proposed parser cannot parse every permitted `each` body.** Parsing the whole step as a formula call fails for `each(targets, roll(1d20) -> it.save_roll)`: the expression parser does not accept `->` inside call arguments. Yet the `Step` type permits any non-`each` inner step. **Change:** specify a step-level grammar that parses `each`’s second argument recursively, using expression-prefix parsing for expression arguments. Add nested-roll acceptance and whole-source limit tests.

4. **vtt-1xv.12, vtt-1xv.20 — should-fix — Acceptance tests depend on unordered producers.** `.12` requires real-server observations before and after Attack actions but does not depend on `.11`, which enables protocol invocation. `.20` requires real Attack invocations and exhaustive rendering of the face effect, but depends on neither `.11` nor `.7`. Its exhaustive renderer can also appear concurrently with `.7`’s promise to update every exhaustive switch. **Change:** record `.12 → .11` and `.20 → .11` dependencies; the latter transitively supplies .7. Alternatively, explicitly rewrite the tests to avoid those unavailable outputs.

5. **vtt-1xv.7, vtt-1xv.12 — blocker — Live action state is being added to a type also used for historical effects.** `ActionView` is currently reused in action-field effects and create/remove snapshots. Making `enabled` required while limiting .12 to object-view conversion leaves historical conversions invalid and forces an undefined choice about evaluating historical actions, including actions on removed objects. Face data is also missing from the specified `ObjectSnapshotView` extension despite the protocol’s lossless GM snapshot requirement. **Change:** distinguish action-definition views from live action-state views; assign ownership of all affected schemas/converters. Include face layouts in create/remove snapshots and test their filtering and preservation.

6. **vtt-1xv.7, vtt-1xv.12 — blocker — Plain face edits need an explicit subscription invalidation path.** `.7` says `setFace` changes no readable cell and introduces `summary.faceChanged`. `.12` only specifies adding candidates whose layouts contain `show_when` or whose actions contain `when`. A plain layout change—or removing the last conditional layout—can therefore produce no object delta. **Change:** explicitly consume `faceChanged` in subscription candidates. Test adding, changing, removing, and undoing an unconditional face against fresh-subscribe equivalence.

7. **vtt-1xv.10, vtt-1xv.12, vtt-1xv.13 — should-fix — Character filtering destroys fixture element indices.** `face_element.element` identifies an element in the stored layout, but character views remove preceding elements and carry no original index. The protocol runner cannot reliably identify the requested element from that reduced array. **Change:** preserve a source index in `FaceElementView`, or define another stable identity and update the fixture contract. Test a visible element following a filtered-out element.

8. **vtt-1xv.14, vtt-1xv.15, vtt-1xv.23 — blocker — Face bounds are not integrated with renderer culling and hit candidates.** Default buttons and contents extend beyond the object footprint. `.14` computes `FaceDrawing.bounds`, but does not specify updating the bounds used by M4’s renderer or replacing footprint-based hit candidates. The renderer hook is called only for items that survive culling. A visible button can disappear when its parent footprint is offscreen, and footprint-based hits cannot reach it. **Change:** define separate presentation bounds for culling and interaction, preserving game geometry. Specify unclipped face-hook rendering and test offscreen parents with visible controls, shapeless binders, rotation, and overlapping faces.

9. **vtt-1xv.16, vtt-3l6.7 — blocker — The drop hook cannot implement the promised template behavior.** M4’s amended hook runs only for move-intent drags. Normal template drags therefore cannot reach a contents/editor override. Moreover, the hook receives Alt at drop, while .16 uses it to choose copy versus move, contradicting the intent fixed at pointer down. **Change:** extend the hook to receive the captured drag intent and support both intents, including spawn-selection continuations. Test changing Alt mid-drag and dropping a board template onto contents and editor elements.

10. **vtt-1xv.18, vtt-1xv.23 — should-fix — Cell dropping “in any tool” has no routing owner.** `.18` implements a layout tool, while .23 merely registers it. The interaction machine routes events to the active tool, so registering `layout` does not make its `data_drop` handler run while another tool is active. **Change:** specify and assign a shared data-drop wrapper or dispatcher, wire it in .23, and test inspector-cell drops while select and ink are active.

11. **vtt-1xv.14, vtt-1xv.17, vtt-1xv.23 — should-fix — The board-template gear has no producer.** `.17` handles a gear on an “entry or board object,” but .14 creates gears only for contents entries. **Change:** assign the board-template affordance to a concrete drawing/hit-test or inspector component and wire it to the binder policy. Add an acceptance case for editing a template placed directly on a board.

12. **vtt-1xv.20 — blocker — Loaded historical pages become stale.** The subscription updates only the newest 200 groups; older pages are fetched once and retained. Hiding an object can leave its old effects visible, and undoing an older group can leave its row unstruck. This violates current-visibility filtering in PROTOCOL §7.6. **Change:** define invalidation/refetch behavior for loaded pages on commits and resync, with revision-aware handling of pending responses. Test visibility changes and undo on groups outside the subscription window.

13. **vtt-1xv.24 — blocker — The required UI fixture execution is impossible as specified.** The Attack fixture deliberately invokes Apply twice; the second button is hidden. Drawing-a-card invokes Draw on an empty deck; the UI’s disabled button deliberately sends nothing. Neither case can produce the required authority rejection through the prescribed click. Action expectations also cannot always inspect a drawn button when `show_when` hides it. **Change:** fix the fallback matrix during planning, including deliberately refused or hidden invocations; separately assert UI suppression and authority refusal. Read action state independently of button visibility. Do not leave the permitted fallback set for the implementer to define.

14. **vtt-1xv.16, vtt-1xv.20 — should-fix — Some Done-when assertions contradict the fixtures.** With `show_when: "not applied"`, Apply starts shown but disabled and disappears after application; it is not “hidden-then-shown” or a “now-disabled button” after Apply. Also, Attack’s Apply group contains damage and `applied` writes, not the roll from the separate Roll damage invocation. **Change:** rewrite these assertions around the actual state transitions and separate action groups.

15. **vtt-1xv.5, vtt-1xv.13 — should-fix — The MCP tool count omits M4’s asset tool.** Current PROTOCOL §11 already lists 18 tools, including `import_asset`. Adding `invoke` yields 19 in the composed process. Requiring 18 risks deleting an existing tool or testing an incomplete composition. **Change:** distinguish base-server and composed-process tool lists, preserve `import_asset`, and assert 19 tools in the final process.

16. **vtt-1xv.16 — should-fix — The interaction bead is too broad for independent review.** It combines invocation/retry handling, button gestures, inline editing, default actions, nested entry dragging, reference drops, container insertion, and lifecycle integration. Those are several independently testable responsibilities with different failure modes. **Change:** split invocation/buttons/editing from entry dragging/drop behavior. Publish their shared policy and gesture contracts first, then make binder behavior depend on the required pieces.

**Overall verdict: not ready to implement.** First supply the missing decision payload, fix transaction ownership and view contracts, close the rendering/drop integration gaps, and make the acceptance mapping executable. Then record the missing dependencies and split the interaction bead before concurrent implementation begins.
